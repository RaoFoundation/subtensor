title: Root dividends
description: How root stake earns through beta baskets — validator curation, share accrual, and fund-level claims.

Stake on the root network (netuid 0) earns dividends from across all subnets.
Since runtime v438 those dividends flow through **beta baskets**: each root
validator runs an escrowed index fund of subnet alpha, curated by its **root
weights**, and root stakers accrue **shares** of that fund which they redeem
for TAO with a single claim. This replaces the old per-subnet claimable
system (`claim_root(subnets)`, `set_root_claim_type`) — see
[migration notes](#migrating-from-v437) below.

Root staking itself is unchanged: moving TAO in and out of root stake is not
a pool swap — no fee, no slippage, no MEV exposure.

## The basket model

Every epoch, a validator's root alpha dividend on each subnet is sold to TAO
and redeployed across the subnets the validator has chosen, in proportion to
its root weights — buying each destination subnet's alpha into the
validator's basket. The basket's holdings are real stake positions held by a
chain-owned **escrow** account, so they keep earning like any other stake.

- **Shares.** When a dividend is deposited, the chain mints basket shares to
  the validator's root stakers in proportion to their root stake, priced at
  the fund's current net asset value (NAV) — exactly like buying into an
  index fund. Your share count only grows until you claim.
- **NAV.** The basket is valued at its *realizable* TAO quote — what selling
  the holdings would actually fetch at current pool depth, net of fees — not
  a spot mark. A thin pool cannot inflate the fund's book value.
- **Netuid 0 slot.** A validator can point part (or all) of its weights at
  netuid 0; that slice is held as TAO (root stake) instead of subnet alpha,
  reducing the basket's subnet exposure.
- **No weights, no basket.** A root validator that never sets root weights
  has its root dividends recycled. Set the vector to start accruing.

## For validators: curate the basket

Set the distribution vector with your **hotkey** (it must be registered on
the root network and hold the minimum stake to set weights; the root weights
rate limit applies):

```bash
btcli weights set-root --weights "0:0.2,4:0.3,8:0.5" -w my_wallet
btcli weights get-root --hotkey 5F...
```

```python
intent = bt.SetRootWeights(netuids=[0, 4, 8], weights=[0.2, 0.3, 0.5])
await client.execute(intent, wallet)
```

Weights are relative — they are normalized and quantized to u16 before
submission ([`set-root-weights`](/docs/tx/set-root-weights)). Every
destination must be netuid 0 or an existing subnet. Read a vector back with
[`validator-root-weights`](/docs/query/validator-root-weights), and inspect
the resulting fund with [`validator-basket`](/docs/query/validator-basket)
and [`validator-basket-nav`](/docs/query/validator-basket-nav):

```bash
btcli stake basket --hotkey 5F...     # per-subnet holdings + NAV
```

Your basket's performance is your pitch to root stakers: dividends compound
inside the fund until claimed, so allocation quality shows up directly in
what stakers redeem.

## For stakers: accrue and claim

Shares accrue automatically — staking TAO on root with a validator is all it
takes. Check what you're owed, then claim:

```bash
btcli stake owed                       # pending TAO, itemized per validator
btcli stake claim -w my_coldkey        # redeem everything, one transaction
```

```python
owed = await client.read("root_basket_owed", coldkey_ss58=wallet.coldkeypub.ss58_address)
await client.execute(bt.ClaimRoot(), wallet)
```

[`claim-root`](/docs/tx/claim-root) takes no parameters: it walks every
validator you root-stake to, redeems your owed shares as a pro-rata slice of
each basket (alpha holdings are sold to TAO at the pool price), and stakes
the proceeds back to root on the same validator.

Two things to know:

- **Claim threshold.** Per-validator payouts below the network threshold
  (default 500,000 rao = τ0.0005, at most τ0.01; read it with
  [`root-claim-threshold`](/docs/query/root-claim-threshold)) are skipped —
  the shares keep accruing and pay out once they clear it. There is no
  deadline and nothing expires.
- **Owed is a live quote.** [`root-basket-owed`](/docs/query/root-basket-owed)
  marks your shares at current pool prices, so the number moves with the
  market — a claim realizes whatever the pools pay at execution time.

## Queries and runtime APIs

Every read is available under `btcli query`, the SDK (`client.read(...)`),
and as `betaBasket_*` RPC methods for integrators:

| Read | What it returns |
|---|---|
| [`root-basket-owed`](/docs/query/root-basket-owed) | Total TAO a coldkey would realize by claiming now |
| [`root-basket-owed-breakdown`](/docs/query/root-basket-owed-breakdown) | The same, itemized per validator hotkey |
| [`validator-basket`](/docs/query/validator-basket) | A validator's holdings: (netuid, alpha, TAO value) rows |
| [`validator-basket-nav`](/docs/query/validator-basket-nav) | A validator's fund NAV in TAO |
| [`root-basket-total-nav`](/docs/query/root-basket-total-nav) | Network-wide basket NAV |
| [`validator-root-weights`](/docs/query/validator-root-weights) | A validator's distribution vector |
| [`root-claim-threshold`](/docs/query/root-claim-threshold) | The minimum per-validator claim payout |

## Migrating from v437

The per-subnet claim model is retired, and the v438 upgrade migrates all
previously accrued claimable alpha into basket holdings — nothing is lost,
it simply becomes fund shares on the same validator.

- `claim_root(subnets)` → [`claim-root`](/docs/tx/claim-root) with **no
  arguments** (fund-level; there is no per-subnet selection anymore).
- `set_root_claim_type` (Swap / Keep / KeepSubnets) is **removed**: payouts
  are always TAO staked back to root. To hold subnet alpha, stake on the
  subnet directly.
- `sudo_set_num_root_claims` is removed; the automatic per-block claim sweep
  is replaced by explicit claims against the fund.
- Hotkey and coldkey swaps carry basket state (holdings, shares, watermarks)
  to the new key; subnet dissolution converts that subnet's basket holdings
  into TAO (root stake) inside each fund.
