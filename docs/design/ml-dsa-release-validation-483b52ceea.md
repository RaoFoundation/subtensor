Local release validation completed for runtime commit `483b52ceea5cf08a0fb492ca2915b7efa6a8690e`. The runtime and its committed reference weights were unchanged throughout this run. One SDK reliability issue was found and fixed locally: a transient, explicit transaction-admission rejection stopped a concurrent operation instead of retrying. The eight operation-family cases were rerun after that fix, together with the entire offline SDK suite and mandatory full preflight. The retry payload and hash were subsequently captured before the first await to prevent caller mutation during backoff; both mutable-object cases passed, and the entire offline SDK suite and full preflight were rerun on that final refinement. Live Python processes already running at the time were not all restarted with the final SDK patch.

The accepted results are **97 live cases, 3,583 Rust tests, 3,585 SDK tests and 8,003 independent cryptographic checks passed**. Rust also reported 47 ignored tests; those are not counted as passed. The SDK count comprises 3,584 passing cases in the full run and the optional Fernet case separately rerun with its dependency. The 20 new admission-retry regression cases are included in that SDK total, not added twice.

The full machine-readable record is [validation-summary.json](evidence/ml-dsa-release-483b52ceea/validation-summary.json). It contains individual test names, timings, source and artifact hashes, accepted and superseded attempts, and a manifest of portable evidence. No wallet secrets, node databases, binaries or mainnet snapshot are included in the portable evidence.

An independent pass verified **768 unique finalized receipts** across 11 suites against canonical blocks, transaction hashes and System/wrapper events: 706 successful outcomes, 19 outer-success/inner-failure outcomes and 43 System failures. Every recorded result agreed with the independently interpreted events. Expected negative cases and recorded transactions from the superseded operation attempt are retained. A separate finalized-state audit of both CLI multisig scenarios verified exact recipient balances of 8 and 9 TAO, member nonces/signing generations, released temporary deposits, and the single intended permanent proxy deposit. Receipt auditing covers persisted receipts, not a claim that every submitted extrinsic was inventoried.

Independent decoder checks round-tripped a finalized block containing all six wallet types using Polkadot.js and PAPI with metadata versions 14, 15 and 16. The current native SDK and a preserved older native binding without ML-DSA exports also decoded versions 14 and 15. Both native bindings already reject metadata version 16; this is a native metadata-support boundary, not a block containing MS signatures failing to decode. This exercised the decoder libraries, not a graphical explorer or every historical client release. The older native binding is identified by its binary hash; its source revision was not independently established.

The independent ML-DSA checks compared the production Rust primitive and matching native SDK with pinned liboqs C and x86-64 implementations, including key/signature agreement, verification in both directions, mutation rejection, contexts, transcripts, HD derivation and descriptor/capability boundaries. The core and JavaScript bindings also built for Wasm, and the Node smoke assertions passed for their exported classical/hashed-classical signing APIs. The Wasm binding does not currently expose an MS signing API; this smoke result is not a browser MS-wallet test. These checks validate implementation behavior; they are not a formal proof or side-channel certification.
