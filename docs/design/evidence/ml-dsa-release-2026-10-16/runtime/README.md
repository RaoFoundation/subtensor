This evidence does **not** establish release readiness. Hostile pre-registration hotkey association can prevent a descriptor-derived account from registering and leave bare-funded TAO without a unilateral recovery route. A separate MEDIUM availability issue allows unknown runtime exports to exhaust admission needed by EVM pending reconstruction. Both are reproduced and remain unresolved in this validation set; reference weights are also excluded at the user's request.

[Runtime review](runtime-review.md) gives the source findings, corrected defects, regressions, exact invariants and remaining policy decisions. [Pending admission follow-up](pending-admission-followup.md) records the residual availability defect and a proposed bounded design; the proposal was not implemented.

The master authentication switch is not a complete emergency spending freeze. It blocks new protected authentication/registration and capability use, while previously approved orders and some cached multisig/proxy authority can still finish through an ordinary relayer. Permanent identity protection survives the pause. A stronger emergency policy requires explicit coordinated gating and revocation/cancellation semantics.

## Evidence boundaries

- [Dispatch matrix](runtime-dispatch-matrix.json): all 326 metadata call variants are accounted for. There are 324 constructible calls tested with real SR, ED, fixed MS and rotating MS envelopes, plus two explicitly uninhabited Grandpa calls. Each mode has 28 included successes, 164 required-origin rejections, 103 included dispatch rejections, 28 validity rejections, and one self-contained-only Ethereum call. The matrix compares exact pool/dispatch outcomes and eight intentional authority-policy differences. This proves envelope/origin parity for those fixtures, not successful business execution of every state and argument combination.
- [Focused runtime log](runtime-hashed-focused.log.gz): 67 selected tests passed, including both MS profiles, owner/proxy/derived restrictions, orders, EVM alias reservation and malformed-faucet input. The hostile-owner regression intentionally proves the unresolved failure case; a passing regression does not make that behavior safe.
- [Production cooldown test](runtime-evm-association-production.log.gz): successful Executive-authenticated EVM association for six wallet families with the actual 7,200-block constant, exact earlier rejection, real secp256k1 proof, and both association indexes. Advancing TestExternalities establishes the boundary without changing chain timing constants.
- [Pending helper evidence](pending-helper/evidence.json): the exact production outcome helper, complete error type and three tests were extracted and linked against the production dependency artifacts. This is narrower than executing the complete Frontier RPC crate suite. The full production node build separately compiled that module.
- [Live populated-pool evidence](live-pending-results.json) and [independent review](live-pending-independent-review.json): 32 submitted transfers, 36 observed pool entries, explicit overload instead of an incomplete successful pending balance, and 32 TAO at a finalized destination. Separate inclusion receipts for every submitted hash are not preserved here.
- [Live isolation reproduction](live-pending-isolation-results.json): four pool entries, healthy pending baseline, 64 unknown-export reads, failed pending balance while latest balance still succeeded, then pending recovery after refill. Only local validator 20245 was probed; no signed transactions or chain writes were submitted. The generic pending error does not identify the exact nested initialization/fallback/apply export that failed.
- [Live MS validator evidence](validator-live/README.md): both fixed and rotating MS passed actual Yuma/Null validator weights, plain and timelocked metadata, encrypted automatic weight reveal and legacy salt reveal. There are 28 finalized successful full-run receipts; all 48 receipts including the preserved fixture-failure attempt were independently checked against canonical finalized blocks and nested outcomes. Normal block timing and supported subnet controls were retained.
- [Mainnet evidence](mainnet/README.md): pinned finalized state, strict upgrade/idempotency checks and ten contiguous synthetic empty post-upgrade blocks with root/signature checks and full-state decode; canonical archived transaction bodies are not replayed. Artifact identities and acquisition/replay provenance are recorded separately from live localnet and test runtime artifacts.

The contracts pallet's tiny migration-budget debug assertion is a preexisting upstream weight issue. Its [reproduction log](runtime-matrix-panic.log.gz) is retained; the matrix supplies the explicit sufficient `migration_noop()` budget. No production filter was added to hide that failure.

Raw JSON, logs and reproduction scripts preserve the local paths and artifact hashes actually used. Shell/Python scripts require their recorded local environment and must not be assumed portable without adapting paths. Markdown reports in this directory have their `/tmp` evidence references adapted to relative paths; raw evidence contents are unchanged. `artifact-manifest.json` hashes every packaged artifact and records current source identities. No snapshot, binary, private wallet material or reference-weight measurement is included.

Raw logs and CLI help are losslessly gzip-compressed with deterministic gzip metadata to preserve their exact bytes and original digests without introducing raw log whitespace into the source diff. Decompress the recorded files before rerunning a checker that expects original .log/.txt names. The manifest records both compressed and uncompressed hashes.
