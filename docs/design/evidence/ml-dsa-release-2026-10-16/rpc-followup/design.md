---
title: "Pending Ethereum RPC admission repair"
description: "Local design review, bounded resource invariants, and regression coverage for the pending-state repair."
---

The original confirmed issue was an availability coupling: unknown raw runtime exports consumed the same Other tokens as pending initialization and pool extrinsic execution. A second issue made a fast 32-transaction reconstruction run out of per-call tokens and discard its partial work. The prior fail-closed change correctly stopped false partial balances, but did not preserve work while waiting for refill.

The repair attaches a process-local PendingExecution extension only in Frontier's pending builder. It has private fields, no SCALE or JSON encoding, and no runtime host function that a raw RPC can call. Node admission checks the actual extension TypeId and narrowly routes only pending block initialization and extrinsic application to a Pending reservation. Merely calling those export names with state_call does not gain that reservation. Unknown exports still use Other even when an internal extension is present.

Pending and Other split the original Other reservation. Each receives one active executor, 8 MiB of active encoded input, an eight-token burst, and four refills per second. Validation, EVM and Contracts retain their original independent reservations. Aggregate ceilings remain eight active metered executions, 64 MiB active encoded input, 64 burst tokens and 32 refills per second. Consensus remains Onchain and unchanged; pending is never mislabeled consensus execution.

An additional whole-job lease admits at most two pending RPC reconstructions in the process. Each pins one pool snapshot, limited to 256 total pool/inherent entries and 8 MiB encoded input. The already pool-bounded ready iterator also clones its index of Arc references; this is not a total heap measurement. Oversized snapshots fail explicitly; they are never silently truncated. Each job retains one absolute 15-second deadline, a cumulative 1,024 executor-attempt cap and a 64 MiB attempted-input cap. The attempt budget is shared by Arc clones and survives transaction rollback. Pending API clones retain the job lease until dropped. These are encoded-input/work bounds, not a claim that total Rust heap usage is exactly the encoded byte count.

Only the exact host execution-capacity error is retried. Each failed attempt rolls back its own transaction; the builder waits outside synchronous Wasm execution, then retries the same initialization/extrinsic on the retained overlay. Successful prior extrinsics are not replayed. Included transaction dispatch failures retain fee/nonce effects, invalid pool transactions are skipped, and invalid/failed inherents abort. Initialization falls back to Core only when the pending export is genuinely absent; overload/traps no longer trigger a second initializer.

The deadline covers provider futures, pending call/estimate backend awaits, all reconstruction retries, and final simulations. A synchronous Wasm call cannot be safely interrupted by cancellation; its execution permit remains held until it returns. A late final simulation result is discarded. Accordingly the deadline is a cooperative bound between synchronous executions, not a host CPU preemption mechanism.

Source tracing showed that Frontier eth_call/estimateGas rebuilt fresh raw overlays, discarding reconstructed pending funding. The corrected baseline live test confirmed the valid value call's pending-funding failure; its gas estimate hit admission capacity. Both repaired paths passed the corrected live comparison. Pending calls now use the same typed runtime ApiRef, and gas probes execute with transaction rollback on that retained state. Every probe resets proof recording and attaches ProofSizeExt to that same ApiRef recorder. Pending simulations preserve supported historical API versions 1–6 and the typed authorization list. Current/latest and historical raw override paths retain their previous behavior and capacity retry. Nonempty state overrides together with pending state are explicitly rejected, because combining those raw overrides with the private ApiRef overlay is unsupported; returning a successful latest-state simulation would be incorrect. Pending storage/code reads now propagate API failures instead of returning empty defaults.

Node regressions exercise actual admission and host budget helpers: raw-export non-forgeability, Other/Pending isolation, unchanged aggregate ceilings, per-service concurrency/bytes, expired final reads versus unaffected latest reads, shared cumulative work, two-job lease lifetime, cancellation release, bounded retries on the same retained state, exact error classification, and existing executor permit retention after caller cancellation. Root-owned production-node live regressions compare malformed floods and 32-transfer pools before/after, pending funding for call/estimate, getter values, repeat simulation state, and explicit pending override rejection. Completed command results and artifacts are recorded in README.md and the adjacent result files.

No on-chain protocol, weight, spec version, dependency, lockfile, hook, commit or push is part of this repair. Dense pending workloads exceeding the documented caps/deadline still return explicit overload; the fix does not promise unbounded availability under same-service saturation.
