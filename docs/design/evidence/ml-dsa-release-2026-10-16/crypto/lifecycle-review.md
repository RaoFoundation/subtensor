title: "Wallet lifecycle and Shield localnet validation"
description: "Independent normal-slot three-validator test environment, execution evidence, fixture changes, and explicit coverage limits."
---

Baseline repository head: `2d5089da3bcb292cbf557d9b22ff34582e23b3f4` plus the shared validation fixes. This localnet uses the parent-built `production/node-subtensor-fixed` and the documented development-weight runtime overlay `test-runtime.wasm`; it does not establish production weight sufficiency. Exact binary, runtime, spec, and test source hashes are in `lifecycle/manifest.json`.

The independent chain uses RPC ports 20144/20145/20146 and peer ports 31134/31135/31136, a unique genesis (Alice's initial nonce is 2), unique protocol/fork IDs, three authorities, and archive state/block pruning. `lifecycle/health-initial.json` confirms all authorities see two peers and the same genesis. `lifecycle/timing.json` proves four consecutive finalized timestamp differences of exactly 12,000 ms, `Timestamp.MinimumPeriod=6000`, and readable genesis runtime state.

`lifecycle/shield-summary.json` records all six key modes passing `test_cross_validator_shield_and_external_nonce_advancement`, including every validator submitting a normal transaction, encrypted success, encrypted included failure, and a client with an older local nonce view signing successfully afterward. Every mode ends with eight nonce increments; registered types also end with eight generation increments. The initial serial run was deliberately interrupted to parallelize independent wallets/sponsors and is not a failed validation. `lifecycle/shield-serial-drain.json` proves its user transaction pool drained and the stop height finalized before rerunning all six cases.

The lifecycle suite preserves the real 7,200-block EVM association cooldown. Its explicit early-height mode requires `EvmKeyAssociateRateLimitExceeded` and no associated address, then continues all remaining lifecycle paths. Successful post-cooldown CLI association is not claimed by this live run; the separate real-runtime Executive regression covers that height. No slot timing or EVM association cooldown was reduced.

Parallel lifecycle setup uses an explicit shared file lock held through finalization for every Alice transaction, reads the new subnet ID from the exact RegisterSubnet result, groups independent root settings atomically, and raises disposable root registration quotas to avoid testing fixture contention. The disposable setup uses the ordinary root configuration calls: PoW difficulty 1, zero transaction/network rate limits and owner freeze limits, enabled subnet registration, and a 2-block coldkey-swap announcement delay with zero reannouncement delay. Those settings are test preconditions, not evidence that default mainnet waiting periods elapsed. Cold/hot registration remains checked at generation zero. All operations performed by wallets under test remain separate transactions. Native call units are RAO; high-level transfers/stakes use their SDK units. The tests use fresh wallet directories and seeds per mode, and restore both roles from their generated mnemonics.

Lifecycle results, final authority health, and shutdown were recorded by the coordinator after completion. A failed suite leaves validators running for diagnosis rather than silently declaring success; on success, the runner terminates only this localnet's launcher and verifies all six dedicated ports close. Raw CLI pytest output is mode 0600 because a failed CLI assertion may contain disposable test secrets; use the sanitized JSON summaries when reporting.

The completed lifecycle cases exercise CLI wallet creation for every scheme/mode; sponsored descriptor registration; zero-balance PoW neuron registration; native and EVM-origin transfers; EVM staking/unstaking; hot/cold role signing; failed-call generation consumption; mnemonic restoration; message verification and HTTP authentication; replay rejection; root registration/staking; proxy execution and protected-delegate restrictions; native-origin EVM calls; and coldkey ownership/stake migration followed by a signature from the replacement wallet. These are explicit integration paths and business-state assertions, not a proof of every possible chain state.

Final outcome: all six lifecycle modes passed; all six Shield modes passed. Final authority health is retained in lifecycle/health-final.json. The owned validator launcher was terminated and every dedicated RPC/P2P port was closed, recorded in lifecycle/shutdown.json.

The first parallel lifecycle attempt exposed a fixture error: batching two classical hashed registrations violates the runtime registration-context invariant. It was corrected to standalone registrations; this was not an authorization defect. Root burn setup was also corrected to respect the production strict lower bound (min 100,000,000 RAO; max 200,000,000 RAO). Interrupted attempts are excluded from pass counts.
