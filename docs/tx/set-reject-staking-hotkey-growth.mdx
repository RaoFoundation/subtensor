Off by default. Incoming transfers can still use hotkeys already listed or
owned by the receiver. A subnet hotkey swap renames an existing entry when
possible; otherwise the receiver's stake stays on the old hotkey. The flag
follows a coldkey swap and does not move funds. The coldkey's own staking
actions remain subject to the overall 256-entry cap.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes | True to refuse third-party staking-list growth; false to allow it up to the third-party cap. |

Address parameters (`--hotkey`, `--coldkey`, `--dest`, ...) accept a raw ss58
address, an address-book or proxy-book name, or a local wallet/hotkey name.

#[pallet::call_index(153)]
#[pallet::weight((<T as Config>::WeightInfo::set_reject_staking_hotkey_growth(), DispatchClass::Normal, Pays::Yes))]
pub fn set_reject_staking_hotkey_growth(
    origin: OriginFor<T>,
    enabled: bool,
) -> DispatchResult {
    let coldkey = ensure_signed(origin)?;
    AccountFlags::<T>::mutate_exists(&coldkey, |stored| {
        let flags = stored.unwrap_or_default();
        let flags = if enabled {
            flags | crate::ACCOUNT_FLAGS_REJECT_STAKING_HOTKEY_GROWTH
        } else {
            flags & !crate::ACCOUNT_FLAGS_REJECT_STAKING_HOTKEY_GROWTH
        };
        *stored = if flags == 0 { None } else { Some(flags) };
    });
    Self::deposit_event(Event::RejectStakingHotkeyGrowthUpdated { coldkey, enabled });
    Ok(())
}
