Pays `amount` of `pay_with` (`tusd` or `tao`) and has the bridge
deliver `receive` to `to_address` on its chain: `stable` (the
stablecoin the bridge locked, one for one against tUSD), `tao`
(canonical TAO, one for one against TAO the hub reserves) or `alpha` (the
alpha token of `netuid`, a share of the stake the hub holds at the
subnet's index hotkey). TAO and tUSD trade through the canonical pool on
the way when the route needs it. The payment settles in this extrinsic or
fails as a whole; the asset arrives on the other chain once the bridge has
relayed the hub's message, usually within a minute. A bridge releases only
the stablecoin it brought in. Fails rather than delivering less than the
current quote less `rate_tolerance`. The coldkey also pays, in TAO and on
top of the amount, the cost of one message to the bridge's chain: it goes
into the bridge's budget, which pays the transport for the message. A
plan's `preview` holds the quote as `receive` and `minimum`, in units
of the delivered asset, and that cost as `message_cost_tao`.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `bridge` | integer | yes | Id of the bridge: 8453 is Base. |
| `pay_with` | string | yes | The asset paid: tusd or tao. |
| `amount` | number | yes | How much of it. |
| `receive` | string | yes | What is delivered: stable, tao or alpha. |
| `to_address` | string | yes | 0x address on the bridge's chain that receives it. |
| `netuid` | integer | no | Subnet of the alpha token, with --receive alpha. |
| `rate_tolerance` | number | no | Maximum fall of what you receive below the current quote, as a fraction (0.05 = 5%). |

Address parameters (`--hotkey`, `--coldkey`, `--dest`, ...) accept a raw ss58
address, an address-book or proxy-book name, or a local wallet/hotkey name.

## Python

```python
import bittensor as bt
from bittensor.wallet import Wallet

wallet = Wallet(name="my_coldkey", hotkey="my_hotkey")
intent = bt.BridgeOut(bridge=0, pay_with="...", amount=1.0, receive="...", to_address="...")

sub = bt.Subtensor()
plan = sub.plan(intent, wallet)   # fee, effects, policy — no submission
result = sub.execute(intent, wallet)
if not result.success:
    print(result.error.code, result.error.remediation)
```

(`bt.Subtensor` is also the async client — `async with bt.Subtensor() as client:`
— see [The client](/docs/concepts/client).) Or build the intent by op name, as
an agent would:

```python
result = sub.execute_tool("bridge_out", {...}, wallet)
```

## On-chain implementation

`Rails.bridge_out` — [`pallets/rails/src/lib.rs#L532`](/code/pallets/rails/src/lib.rs#L530-L556):

```rust
#[pallet::call_index(2)]
#[pallet::weight(<T as Config>::WeightInfo::bridge_out().saturating_add(T::Staking::weight()))]
pub fn bridge_out(
    origin: OriginFor<T>,
    bridge: BridgeId,
    source: NativeAsset,
    amount: u64,
    destination: Destination<T::AccountId>,
    min_out: u64,
) -> DispatchResult {
    let who = ensure_signed(origin)?;
    ensure!(!Paused::<T>::get(), Error::<T>::Paused);
    Self::ensure_bridge_enabled(bridge)?;
    let fee = MessageCost::<T>::get(bridge).ok_or(Error::<T>::MessagesNotFunded)?;
    let amount_out =
        Self::route_native(&who, bridge, source, amount, &destination, min_out)?;
    Self::deposit_event(Event::BridgedOut {
        who,
        bridge,
        source,
        amount,
        destination,
        amount_out,
        fee,
    });
    Ok(())
}
```
