The chain stores the url and the spender only; the document the url points
to (the services and their interfaces) is the publisher's. Without
`spender_ss58` the service keeps its spender, which for a new service is
the hotkey. Signed by the hotkey, which must be registered on the subnet,
and free, as serving an axon is. An empty url clears the service. Updates
wait out the subnet's `serving_rate_limit`.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `netuid` | integer | yes | Subnet on which to publish the service. |
| `url` | string | yes | An http(s) url of the services document, up to 256 bytes; empty clears it. |
| `spender_ss58` | string | no | The spender customers name for the service. Omit to keep the current one, which for a new service is the hotkey. |

Address parameters (`--hotkey`, `--coldkey`, `--dest`, ...) accept a raw ss58
address, an address-book or proxy-book name, or a local wallet/hotkey name.

## CLI

Preview with `--dry-run` (shows fee, effects, and policy result without
submitting), then submit:

```bash
btcli tx set-service \
  --netuid <int> \
  --url <value> --dry-run
btcli tx set-service \
  --netuid <int> \
  --url <value> -w my_coldkey
```

## Python

```python
import bittensor as bt
from bittensor.wallet import Wallet

wallet = Wallet(name="my_coldkey", hotkey="my_hotkey")
intent = bt.SetService(netuid=1, url="...")

sub = bt.Subtensor()
plan = sub.plan(intent, wallet)   # fee, effects, policy — no submission
result = sub.execute(intent, wallet)
if not result.success:
    print(result.error.code, result.error.remediation)
```

(`bt.Subtensor` is also the async client — `async with bt.Subtensor() as client:`
— see [The client](/docs/concepts/client).) Or build the intent by op name, as
an agent would:

```python
result = sub.execute_tool("set_service", {...}, wallet)
```
