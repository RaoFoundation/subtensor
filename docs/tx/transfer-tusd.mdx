tUSD is the chain's dollar: bridges mint it one for one against a
stablecoin they lock on another chain. A transfer is irreversible. An
account holds no tUSD or at least 0.01, so a transfer that would leave less
than that on either side fails: send the whole balance instead.

| Signer | Origin | Pallet | Wraps |
| --- | --- | --- | --- |
| `coldkey` | signed account (pallet role may apply) | Tusd | [`Tusd.transfer`](/code/pallets/tusd/src/lib.rs#L213-L223) |

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `dest_ss58` | string | yes | Destination account that receives the tUSD. |
| `amount_tusd` | number | yes | tUSD sent. |

Address parameters (`--hotkey`, `--coldkey`, `--dest`, ...) accept a raw ss58
address, an address-book or proxy-book name, or a local wallet/hotkey name.

## CLI

Preview with `--dry-run` (shows fee, effects, and policy result without
submitting), then submit:

```bash
btcli tx transfer-tusd \
  --dest <ss58|name> \
  --amount-tusd <amount> --dry-run
btcli tx transfer-tusd \
  --dest <ss58|name> \
  --amount-tusd <amount> -w my_coldkey
```

## Python

```python
import bittensor as bt
from bittensor.wallet import Wallet

wallet = Wallet(name="my_coldkey", hotkey="my_hotkey")
intent = bt.TransferTusd(dest_ss58="5G...destination", amount_tusd=1.0)

sub = bt.Subtensor()
plan = sub.plan(intent, wallet)   # fee, effects, policy — no submission
result = sub.execute(intent, wallet)
if not result.success:
    print(result.error.code, result.error.remediation)
```

(`bt.Subtensor` is also the async client — `async with bt.Subtensor() as client:`
— see [The client](/docs/concepts/client).) Or build the intent by op name, as
an agent would:

```python
result = sub.execute_tool("transfer_tusd", {...}, wallet)
```
