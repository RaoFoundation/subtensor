Sells `amount` of `sell` (`tusd` or `tao`) for the other asset at
the pool's price, less its fee, which stays in the pool for its liquidity
providers. Fails rather than receiving less than the current quote less
`rate_tolerance`. The pool caps one swap at a fraction of its depth and
rate-limits each direction, so a large amount may need several swaps. A
plan's `preview` holds the quote as `receive` and `minimum`.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `sell` | string | yes | The asset sold: tusd or tao. |
| `amount` | number | yes | How much of the sold asset. |
| `rate_tolerance` | number | no | Maximum fall of what you receive below the current quote, as a fraction (0.05 = 5%). |

Address parameters (`--hotkey`, `--coldkey`, `--dest`, ...) accept a raw ss58
address, an address-book or proxy-book name, or a local wallet/hotkey name.

## CLI

Preview with `--dry-run` (shows fee, effects, and policy result without
submitting), then submit:

```bash
btcli tx swap-pool \
  --sell <value> \
  --amount <amount> --dry-run
btcli tx swap-pool \
  --sell <value> \
  --amount <amount> -w my_coldkey
```

## Python

```python
import bittensor as bt
from bittensor.wallet import Wallet

wallet = Wallet(name="my_coldkey", hotkey="my_hotkey")
intent = bt.SwapPool(sell="...", amount=1.0)

sub = bt.Subtensor()
plan = sub.plan(intent, wallet)   # fee, effects, policy — no submission
result = sub.execute(intent, wallet)
if not result.success:
    print(result.error.code, result.error.remediation)
```

(`bt.Subtensor` is also the async client — `async with bt.Subtensor() as client:`
— see [The client](/docs/concepts/client).) Or build the intent by op name, as
an agent would:

```python
result = sub.execute_tool("swap_pool", {...}, wallet)
```
