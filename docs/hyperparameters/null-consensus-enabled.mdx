---
title: "null_consensus_enabled"
description: "Switch an existing subnet between Yuma and equal miner emissions without epochs."
---

New subnets start with Yuma 3 and this flag disabled. The owner or root can toggle
`null_consensus_enabled` through `AdminUtils.sudo_set_null_consensus_enabled`.
Other hyperparameters and both miner registries are preserved.

```bash
btcli hparams set --netuid 123 --name null_consensus_enabled --value true
btcli hparams set --netuid 123 --name null_consensus_enabled --value false
```

Null consensus pays every registered null miner equally after the owner cut,
without weights, bonds, or epochs. Yuma weights and commit-reveal configuration
remain stored. Disabling null mode resumes the configured Yuma version.
Owner rate limits apply in both modes; the epoch freeze window applies only in Yuma.

Enabling requires one mechanism and no pending encrypted Yuma submissions.
`NullConsensusPendingWeightCommits` means those submissions must finish revealing
first. If validators keep replenishing the queue, disable
`commit_reveal_weights_enabled`, wait for outstanding reveals, and retry the
null toggle. The toggle itself never changes that hyperparameter.

The initial Yuma metagraph import must fit its normal capacity. The independent
null registry uses `u64` identifiers, and its population does not prevent
switching back to Yuma. See [null-consensus subnets](/guides/null-consensus).
