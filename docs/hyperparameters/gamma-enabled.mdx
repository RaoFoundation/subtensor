`gamma_enabled` lets coldkeys mint the subnet's [gamma](/docs/guides/gamma) by
burning its alpha. Subnet owners that sell a service for gamma turn it on; no
other gamma call checks it, so deposits stay spendable, movable and closable
while it is off.

## How it works

The flag lives in
[`SubnetGammaEnabled`](/code/pallets/subtensor/src/lib.rs#L3895) storage and
defaults to **false**. A mint also needs gamma enabled network-wide, in
[`GammaEnabled`](/code/pallets/subtensor/src/lib.rs#L3891), which defaults to
**false** and only root sets
([`sudo_set_gamma_enabled`](/code/pallets/admin-utils/src/lib.rs#L2926-L2932)).
A subnet can turn its flag on before that, and mints once both are on.

Neither flag touches the subnet's gamma price
([`SubnetGammaPrice`](/code/pallets/subtensor/src/lib.rs#L3926)), which every
subnet but root keeps
([`update_gamma_price`](/code/pallets/subtensor/src/staking/stake_utils.rs#L115-L123));
a mint values alpha at the lower of the gamma price and the spot price
([`gamma_mark`](/code/pallets/subtensor/src/subnets/gamma.rs#L96-L99)). See
[Minting](/docs/guides/gamma#minting).

The subnet owner or root sets `gamma_enabled`
([`sudo_set_subnet_gamma_enabled`](/code/pallets/admin-utils/src/lib.rs#L2894-L2920));
the owner is rate-limited, both are refused during the admin freeze window, and
the root subnet cannot enable it.

## Reading and setting

```bash
btcli sudo get --netuid N --name gamma_enabled
btcli sudo set --netuid N --name gamma_enabled --value true
```
